# ADMIN USAGE

Инструкция по admin bot и web admin panel.

## 1. Общая идея

У администратора есть два интерфейса:

- Telegram admin bot для быстрых operational-действий
- web admin panel для полной работы с системой

Оба интерфейса используют одну и ту же бизнес-логику и одну БД.

## 2. Доступ к admin bot

Admin bot пускает только тех, кто:

- указан в `ADMIN_TELEGRAM_IDS`
- или создан как `admin_user` в локальной БД

Если Telegram ID не авторизован, бот ответит отказом.

## 3. Основные разделы admin bot

- `Заявки`
- `Пользователь`
- `Серверы`
- `Статистика`
- `Помощь`

### `Заявки`

Показывает новые заявки на пополнение.

Из карточки заявки можно:

- подтвердить пополнение
- отклонить заявку

После подтверждения:

- баланс пользователя увеличивается
- создаётся запись в `balance_transactions`
- пользователю уходит уведомление

### `Пользователь`

Бот попросит отправить:

- Telegram ID
- или username

После поиска откроется карточка пользователя:

- статус
- баланс
- текущий тариф
- дата продления

Из карточки можно:

- выдать trial
- активировать безлимит
- активировать тариф 50 ГБ
- скорректировать баланс
- заблокировать доступ

### `Серверы`

Показывает:

- список серверов
- online/offline
- текущую нагрузку
- число клиентов

Если список пуст, бот инициирует sync из Remnawave.

### `Статистика`

Показывает:

- активных пользователей
- пользователей в grace
- заблокированных
- test users
- новые заявки
- онлайн
- общую сумму задолженности
- топ пользователей по трафику

## 4. Web admin panel

Разделы панели:

- `Dashboard`
- `Пользователи`
- `Серверы`
- `Заявки`
- `Тарифы`
- `Баланс`
- `Трафик`
- `Онлайн`
- `Настройки`
- `Логи`

## 5. Dashboard

Показывает:

- активных клиентов
- клиентов в grace period
- заблокированных
- тестовых
- новые заявки
- суммарный трафик
- задолженности
- загрузку серверов
- топ пользователей по трафику

## 6. Пользователи

Список пользователей поддерживает поиск по:

- Telegram ID
- username
- имени

В карточке пользователя доступны:

- профиль и баланс
- текущая подписка
- история пополнений
- история транзакций
- список доступных серверов
- уведомления
- ручная корректировка баланса
- выдача trial
- ручная активация тарифа
- ручная блокировка

## 7. Серверы

Раздел `Серверы` показывает:

- Remnawave node name
- страну
- online/offline
- клиентов / лимит
- нагрузку
- число inbound'ов

Доступные действия:

- синхронизация списка серверов из Remnawave
- локальное включение/выключение сервера
- установка `max_clients_count`
- удаление сервера из локальной системы управления

Важно:

- удаление из локальной системы не удаляет node в Remnawave
- это только локальный флаг участия сервера в ALTLINK

## 8. Заявки на пополнение

Раздел показывает:

- дату
- сумму
- пользователя
- статус
- комментарии

Можно:

- подтвердить
- отклонить

## 9. Тарифы

Раздел показывает засеянные тарифы:

- `trial_2d`
- `unlimited_30d`
- `limited_50gb_30d`

## 10. Баланс и транзакции

Показывает:

- тип транзакции
- сумму
- баланс до/после
- комментарий
- связь с заявкой или подпиской

## 11. Трафик и лимиты

Раздел показывает по подпискам:

- текущий статус
- использованный трафик
- лимит
- период
- задолженность

Для лимитного тарифа блокировка происходит после достижения 100% лимита.

## 12. Онлайн клиенты

Раздел показывает best-effort данные, которые удалось получить через официальный API Remnawave:

- IP
- user-agent / device hint
- сервер
- последнюю активность
- online flag

Если inbound не возвращается официальным API, в UI будет показано:

```text
API не предоставляет
```

## 13. Настройки

Содержит значения из `system_settings`, например:

- `traffic_notify_thresholds`
- `low_balance_threshold_rub`
- `low_balance_notify_days`
- `trial_duration_days`
- `grace_period_days`

## 14. Логи

Раздел `Логи` показывает записи `system_events`.

Там видно:

- scope задачи
- уровень
- заголовок
- детали

Это основной operational журнал фоновых задач и ключевых системных событий.

## 15. Практический рабочий процесс

Обычный daily flow администратора:

1. открыть `Заявки` в admin bot или web panel
2. подтвердить новые пополнения
3. проверить `Dashboard`
4. проверить `Серверы` и нагрузку
5. при необходимости открыть карточку пользователя
6. скорректировать баланс / выдать trial / активировать тариф / заблокировать доступ

## 16. Важные operational замечания

- grace speed limiting не применяется, потому что официальный API Remnawave этого не поддерживает явно
- per-server отдельной подписки нет, используется нативная общая подписка Remnawave
- web panel и admin bot работают поверх одной логики, поэтому действия из любого интерфейса сразу видны в другом
