# ALTLINK audit: 2026-09-12

Final verification continued on 2026-09-13.

Scope: billing and activation, payment entry points, promo redemption, bot
handlers, web authentication, subscription links, admin pages, notifications,
schema migrations, and responsive portal/landing UI. This is a code and local
runtime review, not a claim that every production failure has been eliminated.

## Confirmed Issues Fixed

| Priority | Issue | Resolution |
| --- | --- | --- |
| P1 | Missing YooKassa credentials selected the test provider and credited real user balances without payment. | Manual approval fallback; explicit stub checkout is unavailable in production. |
| P1 | Failed remote activation could commit a trial, charge, or plan-switch refund when UI handlers caught the exception. | A per-user lock and database savepoint protect trial and paid activation. |
| P1 | An inactive admin could reuse an existing signed web session. | Resolve the active flag on every authenticated admin request. |
| P1 | The built-in admin API accepted the public example key. | Empty/default API keys fail closed; configured keys use constant-time comparison. |
| P2 | Missing CSRF tokens could compare equal; logout did not validate CSRF. | Require matching nonempty tokens, including logout; reject malformed JSON objects. |
| P2 | Telegram auth accepted future timestamps; malformed signatures could raise exceptions. | Timestamp bounds, signature shape, duplicate Mini App field and user-ID validation. |
| P2 | HTTPS session cookies lacked Secure. | Set Secure when the public backend URL is HTTPS; retain local HTTP development. |
| P2 | SQL error output could include sensitive query parameters, including node configuration. | Hide SQL parameters in application engine logging and exceptions. |
| P2 | `/admin/traffic` failed to render due to float multiplied by Decimal. | Keep price calculation in Decimal arithmetic and round the estimate to kopecks. |
| P2 | Nonfinite or oversized user-filter values could cause database errors. | Validate numeric bounds before building SQL filters. |
| P2 | Portal price cards did not reflect a pending promo discount or update after redemption. | Read the pending discount once, use billing rounding, update prices and balance in-place. |
| P2 | Clipboard API rejection prevented a working WebView fallback; failed legacy copy could report success. | Try both methods, check the result, and show failure rather than a false success. |
| P3 | Long mobile account names displaced useful content far below the first screen. | Preserve large typography but clamp names to two lines; retain full text in the DOM/title. |
| P3 | Theme controls lost manual selection when localStorage was unavailable. | Keep an in-page preference and synchronize storage changes across tabs. |

## Remaining Risks / Follow-Up

1. **P1, configuration:** `Settings` still has example session secrets. Deployment
   must replace every `change-me*` value, especially `SESSION_SECRET_KEY`.
   The API example key is blocked, but session-secret safety is not enforced at
   startup. Production secrets were not inspected or changed in this audit.
2. **P2, notification delivery:** `NotificationService.dispatch_pending` marks
   every sending exception FAILED. Temporary Telegram failures/429 are not
   retried automatically. Outcomes are written after the whole batch; a crash
   after sending and before commit can cause duplicate delivery. Add a leased
   outbox, bounded backoff, and separate transient/permanent failures. Merely
   retrying all FAILED rows could resend old marketing messages and is unsafe.
3. **P2, distributed consistency:** savepoints guarantee local rollback, not
   rollback of successful Remnawave calls. A successful remote change followed
   by a later local failure still needs reconciliation. Test a durable remote
   synchronization queue before changing this behavior in production.
4. **P3, maintenance:** admin payment formatting helpers have multiple definitions
   in `admin_handlers.py`; the last definitions currently win. Consolidate them
   separately with bot text regression tests to avoid editing inactive code.
5. **P3, accessibility:** portal modal buttons work by pointer/tap, but consistent
   Escape handling, focus trapping, and focus restoration still need work.
6. **P2, reproducible builds:** dependencies use version ranges and the Dockerfile
   upgrades pip without a lockfile. A rebuild can resolve a different dependency
   set even when application code is unchanged. Keep a tested lock/constraints
   file and update it deliberately; this audit does not freeze upgrade policy.

Limitations: the full suite uses SQLite and mocked external services on Python
3.13 and in a fresh Python 3.12 Docker image, supplemented by the focused
PostgreSQL checks above. This does not replace real Telegram iOS/Android WebView
testing, actual YooKassa payment confirmation, or device-side Happ/INCY imports.
The production database, existing containers, and live users were not modified.

No new database migration is required by these audit fixes. See `DEPLOYMENT.md`
for the changed payment fallback, API key, and HTTPS-cookie requirements.
