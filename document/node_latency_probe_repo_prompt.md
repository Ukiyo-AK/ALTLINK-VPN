# Prompt: Node Latency Probe Service

Создай отдельный production-ready репозиторий `altlink-node-probe` для мини-сервиса, который будет разворачиваться на каждой VPN-ноде и использоваться браузером клиента для измерения RTT.

Требования:

1. Стек:
- Python 3.12
- FastAPI
- Uvicorn
- Dockerfile
- docker-compose.yml
- README.md с инструкцией запуска

2. Назначение:
- сервис слушает `0.0.0.0:44443`
- endpoint `GET /ping`
- endpoint `HEAD /ping`
- endpoint `GET /health/live`
- `GET /ping` и `HEAD /ping` должны отвечать максимально быстро, без БД и без внешних зависимостей
- для `/ping` вернуть `204 No Content`
- для `/health/live` вернуть JSON `{"ok": true}`

3. Важные требования:
- сервис не должен требовать авторизацию
- сервис не должен логировать лишние данные запроса
- сервис должен быть лёгким и устойчивым
- нужен healthcheck для Docker
- нужен graceful shutdown
- нужно ограничить ответ только этими endpoint'ами
- остальные пути должны возвращать `404`

4. HTTPS:
- repo должен содержать пример запуска через Caddy
- внешний доступ должен быть по `https://<node-domain>:44443/ping`
- Caddy должен терминировать TLS
- приложение FastAPI внутри контейнера может работать по обычному HTTP на внутреннем порту, например `8080`
- в README объясни, что для browser-side latency нужны валидные TLS-сертификаты и публичный домен на каждой ноде

5. CORS:
- так как ALTLINK будет вызывать endpoint из браузера с `fetch(..., { mode: "no-cors" })`, обязательной CORS-настройки не нужно
- но в README объясни, почему выбран именно такой режим

6. Структура repo:
- `app.py`
- `requirements.txt`
- `Dockerfile`
- `docker-compose.yml`
- `Caddyfile`
- `README.md`
- `.dockerignore`

7. README должен содержать:
- что делает сервис
- как запустить локально
- как запустить через Docker Compose
- как привязать домен ноды
- как открыть порт `44443`
- как проверить руками:
  - `curl -I https://node.example.com:44443/ping`
  - `curl https://node.example.com:44443/health/live`

8. Код нужен чистый и минималистичный:
- без лишней архитектурной сложности
- без БД
- без Redis
- без auth
- без фоновых задач

9. Отдельно:
- добавь в README раздел “Почему не ICMP ping из браузера”
- коротко объясни, что браузер не умеет делать настоящий ICMP, поэтому используется RTT до HTTPS probe endpoint
